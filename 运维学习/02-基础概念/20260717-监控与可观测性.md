# 监控与可观测性

## 是什么

监控告诉你「系统坏了没有」，可观测性告诉你「为什么坏了以及怎么修」。三根支柱：**日志（Logs）** 记录事件、**指标（Metrics）** 量化状态、**链路追踪（Traces）** 还原调用路径。

## 为什么重要

没有监控，线上故障靠用户电话通知。有了监控+可观测性，你能在用户察觉之前发现问题，在 3 分钟而不是 3 小时内定位根因。这是运维从「救火」到「预防」的关键跨越。

## 核心要点

- **Prometheus + Grafana** 是事实标准：Prometheus 拉取并存储时序指标，Grafana 画仪表盘和配告警。
- **ELK / Loki** 管日志：Elasticsearch 重量但功能全，Loki 轻量且和 Prometheus 标签体系一致。
- **分布式追踪**（Jaeger / Tempo）：还原一个请求经过 N 个微服务的完整链路，哪个节点拖后腿一目了然。
- **四个黄金信号**：延迟（Latency）、流量（Traffic）、错误率（Errors）、饱和度（Saturation）——任何服务盯着这四个就够了。
- **告警不是越多越好**：告警疲劳比没告警更危险。只对用户可感知的问题告警，其他记日志就行。

## 一句话带走

> 监控是仪表盘，可观测性是探针。前者看仪表亮灯，后者能诊断为什么亮灯。
