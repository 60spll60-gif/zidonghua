# CI 与 CD

## 是什么

**CI（持续集成）**：代码一提交，自动跑测试、构建、检查——确保新代码不弄坏旧功能。**CD 有两层**：持续交付（自动构建出可部署的产物）和持续部署（自动把产物推到生产环境）。

## 为什么重要

没有 CI/CD，上线靠手动——复制文件、重启服务、祈祷不出错。有了 CI/CD，你 push 代码，剩下的机器自动干。从「上线恐惧症」到「一天发十版」的转变就靠它。

## 核心要点

- **流水线（Pipeline）**：一条流水线 = 多个阶段（Stage），每个阶段 = 多个任务（Job）。阶段之间串行，任务之间可并行。
- **常见流程**：Push 代码 → 自动拉取 → 安装依赖 → 跑测试 → 构建镜像 → 推送到镜像仓库 → 部署到测试环境 → 跑 E2E 测试 → 部署到生产。
- **GitLab CI**：用 `.gitlab-ci.yml` 定义流水线，Runner 执行任务。GitHub Actions 同理，用 `.github/workflows/*.yml`。
- **回滚是底线**：每次部署必须保留上一版本，出问题一键回滚——不能因为自动化就放弃可逆性。
- **不要一开始追求全自动**：先做到自动测试+自动构建，稳定后再加自动部署。逐步来，别一口吃成胖子。

## 一句话带走

> CI 管「代码对不对」，CD 管「代码上没上线」。合在一起就是：你只管写好代码，剩下交给机器。
