# 容器化部署实践

## 目标

把一个实际应用（比如你写的 Python Web 项目）从「手动部署」改造为「一条命令部署」的容器化方案，覆盖开发 → 测试 → 生产的完整链路。

## 关键任务

- [ ] 选一个实际项目：可以是 Flask/FastAPI Web 应用，或者一个定时任务脚本
- [ ] 写 Dockerfile：多阶段构建——第一阶段装依赖，第二阶段只保留运行时
- [ ] 写 docker-compose.yml：Web 服务 + 数据库 + Redis 缓存，一个 `up` 全启动
- [ ] 本地测试：`docker-compose up` 确认服务正常，curl/pytest 验证
- [ ] 推送镜像：打 tag，push 到 Docker Hub 或私有 Registry（Harbor）
- [ ] 部署到服务器：在云服务器或家庭服务器上 `docker-compose pull && up -d`
- [ ] 配置自动更新：用 Watchtower 自动拉新镜像，或结合 GitLab-CI 自动触发
- [ ] 加健康检查：`HEALTHCHECK` 指令 + `depends_on` condition，服务挂了自动重启

## 验收标准

- `git clone` 后一条 `docker-compose up -d` 能跑起来
- 数据库数据持久化（容器重启不丢）
- 日志可查看（`docker-compose logs`）
