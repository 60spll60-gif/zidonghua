# Docker 实践

## 是什么

Docker 是容器化的事实标准。它能在一台机器上跑多个互相隔离的应用，每个应用带着自己的运行环境（依赖、配置、系统库），互不干扰。

## 为什么重要

「在我机器上能跑」的终极解决方案。开发环境、测试环境、生产环境——三个地方用同一个 Docker 镜像，环境差异归零。

## 常用命令速查

```bash
# 镜像管理
docker pull nginx:latest          # 拉镜像
docker images                     # 看本地镜像
docker rmi <image_id>             # 删镜像
docker build -t myapp:v1 .        # 用 Dockerfile 构建

# 容器管理
docker run -d -p 8080:80 --name web nginx   # 后台运行，端口映射
docker ps                         # 看运行中的容器
docker logs -f web                # 实时看日志
docker exec -it web bash          # 进容器内 Shell
docker stop web && docker rm web  # 停掉并删除

# 调试
docker inspect web                # 看容器详细信息
docker stats                      # 实时资源占用
docker system prune -a            # 清理无用的镜像/容器/网络
```

## 核心要点

- **Dockerfile 最佳实践**：多阶段构建减小镜像体积；`.dockerignore` 排除无用文件；尽量用官方镜像做基础。
- **docker-compose**：一个 YAML 管多个容器。`depends_on` 控制启动顺序，`volumes` 挂载持久化数据。
- **网络**：默认 bridge 网络容器间可用服务名互相访问；`docker network create` 建自定义网络隔离环境。
- **不要往容器里写数据**：容器删了数据就没了——数据必须挂载 volume 或 bind mount 到宿主机。

## 一句话带走

> Docker 让应用变成「集装箱」——从开发到生产，全程统一格式，到哪儿都能跑。
