# GitLab-CI 实践

## 是什么

GitLab-CI 是 GitLab 内置的 CI/CD 系统。在项目根目录放一个 `.gitlab-ci.yml`，每次 push 代码，GitLab 自动按你定义的流水线跑测试、构建、部署。

## 为什么重要

免费用、无需额外搭 Jenkins、和 GitLab 仓库深度集成——中小团队 CI/CD 入门首选。Merge Request 里直接看到流水线状态，测试没过就不让合并。

## 一个最小可用的 .gitlab-ci.yml

```yaml
stages:
  - test
  - build
  - deploy

test:
  stage: test
  image: python:3.12
  script:
    - pip install -r requirements.txt
    - pytest
  only:
    - merge_requests

build:
  stage: build
  image: docker:latest
  services:
    - docker:dind
  script:
    - docker build -t myapp:$CI_COMMIT_SHORT_SHA .
    - docker push myapp:$CI_COMMIT_SHORT_SHA
  only:
    - main

deploy:
  stage: deploy
  script:
    - kubectl set image deployment/myapp app=myapp:$CI_COMMIT_SHORT_SHA
  only:
    - main
  when: manual   # 手动触发部署，不自动
```

## 核心要点

- **Runner**：执行流水线的机器。可用 GitLab 共享 Runner（免费有限额），也可自建 Runner（Docker 一条命令起一个）。
- **Stage 串行，Job 并行**：同一 stage 里的 job 同时跑；下一 stage 等上一 stage 全部通过才启动。
- **artifacts**：把构建产物（编译好的二进制、测试报告）传给后续 job。
- **Cache vs Artifacts**：cache 存依赖（pip/node_modules），可跨流水线复用；artifacts 存产物，只在同一次流水线内传递。
- **环境变量**：在 GitLab 项目 Settings → CI/CD → Variables 里设，敏感信息（密码/Token）一定要设成 Masked+Protected。

## 一句话带走

> Push 代码 → GitLab-CI 自动测试 → 自动构建 → 手动确认部署。你只管写好 `.gitlab-ci.yml`，剩下的不操心。
