# Linux 网络与排错

## 一、先分层，再执行命令

网络问题不要凭感觉反复重启。可以从「本机接口 → 路由 → DNS → TCP 端口 → 应用协议」逐层验证。

```bash
ip addr                     # 网卡和 IP 地址
ip route                    # 路由表和默认网关
ping -c 4 127.0.0.1        # 验证本机协议栈
ping -c 4 <网关 IP>          # 验证局域网连通性
ping -c 4 1.1.1.1           # 验证外网 IP 连通性
getent hosts example.com    # 验证 DNS 解析
```

## 二、端口与连接

端口是传输层的入口。监听端口只能说明程序绑定了端口，不代表应用一定能正确处理请求。

```bash
ss -lntp                   # TCP 监听端口及关联进程
ss -ant                    # 全部 TCP 连接状态
curl -I http://127.0.0.1:8080  # 验证 HTTP 响应
nc -vz 127.0.0.1 22       # 验证 TCP 端口是否可达
```

常见状态：`LISTEN` 表示监听，`ESTAB` 表示已建立连接，`TIME-WAIT` 是连接关闭后的正常等待状态。不要看到 `TIME-WAIT` 就直接调内核参数，先确认是否真的影响业务。

## 三、实用排错路径

以「网页打不开」为例：

1. `curl -I URL`：先看是否能得到 HTTP 响应。
2. `getent hosts 域名`：确认域名是否解析到预期地址。
3. `ip route get 目标 IP`：确认流量走哪条路由。
4. `ss -lntp`：服务是否监听正确地址和端口。
5. `journalctl -u 服务名`：查看服务日志。
6. 检查防火墙、安全组、反向代理和应用日志。

## 一句话带走

> 网络排错要把「解析失败、路由失败、端口不通、协议报错、应用异常」分开验证，每一步都留下证据。
