# Linux 进程与服务

## 一、进程观察

进程是程序运行后的实例，每个进程都有 PID、父进程、用户、状态和资源占用。

```bash
ps aux                       # 查看当前系统进程
ps -ef --forest              # 查看父子进程关系
top                          # 实时查看 CPU、内存和负载
pgrep -af nginx              # 按名称查找 PID 和完整命令
```

排查时先记录 PID，再看命令和日志，不要一上来就 `kill -9`。常见信号包括：`SIGTERM`（15，礼貌请求退出）、`SIGKILL`（9，无法捕获的强制终止）和 `SIGHUP`（1，常用于重新加载配置）。

```bash
kill -TERM <PID>             # 优先请求程序自行退出
kill -KILL <PID>             # 程序失控时最后使用
jobs -l                      # 查看当前 Shell 的后台任务
fg %1                        # 将后台任务带回前台
```

## 二、systemd 服务

现代 Linux 常用 `systemd` 管理系统服务。`systemctl` 管理生命周期，`journalctl` 查看日志。

```bash
systemctl status ssh         # 查看服务状态
sudo systemctl restart ssh   # 重启服务
sudo systemctl enable --now ssh  # 设置开机启动并立即启动
journalctl -u ssh -n 50 --no-pager
journalctl -u ssh --since '1 hour ago'
```

「进程存在」不等于「服务健康」。服务排错通常按以下顺序：

1. `systemctl status 服务名`：是否启动、是否反复崩溃。
2. `journalctl -u 服务名`：启动失败的直接原因。
3. `ss -lntp`：是否监听预期端口。
4. 配置检查命令和应用自身日志：配置语法、依赖和权限是否正确。

## 三、资源与信号的边界

- CPU 高：先用 `top` 定位进程，再查看线程、请求和日志。
- 内存高：区分真实占用、缓存和 OOM；查看 `free -h` 与 `dmesg`。
- 磁盘满：查看 `df -h`（文件系统）和 `du -xhd1`（目录），两者回答的问题不同。
- 服务异常：先优雅停止和保留现场，再决定是否强杀。

## 一句话带走

> 进程是运行实例，服务是可管理的运行单元；`ps/top` 看现状，`systemctl/journalctl` 查服务生命周期和原因。
