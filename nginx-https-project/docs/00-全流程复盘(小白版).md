# Nginx HTTPS 项目 · 全流程复盘（小白版）

> 这份文档把整个项目用"大白话 + 生活比喻"重新讲一遍。
> 每个步骤都告诉你 **做什么 → 为什么 → 不这样做会怎样**。
> 看完你不仅记得住命令，更懂得背后的道理。

---

## 🏠 先用一个比喻理解全局

把你的服务器想象成**开一家网店**：

| 项目里的东西 | 比喻 |
|--------------|------|
| 阿里云服务器 | 你租的**店面** |
| Linux系统 | 店面的**毛坯房** |
| SSH / Workbench | 进店的**钥匙** |
| Nginx | 店里的**接待员**（负责把网页递给访客） |
| 防火墙(ufw) | 店门的**门禁**（只开该开的门） |
| SSL证书 | 店的**正规营业执照+保险柜**（证明是正店，聊天内容加密） |
| HTTPS | 给店装**隔音玻璃**（路人偷听不到里面的话） |
| 知识库仪表盘 | 你店的**招牌商品** |
| ICP备案 | 工商**登记备案**（国内开店必须） |

整个项目，就是**毛坯房 → 装修 → 开业 → 加密经营**。

## 📍 第一阶段：拿到店面，进店

### 做了什么
登录阿里云 → 买轻量服务器(Ubuntu 22.04) → SSH连接 → `sudo -i`切root

### 为什么
- **为什么选 Ubuntu 不选宝塔面板？**
  宝塔是"精装样板间"，鼠标点点就开业了，但你学不到手艺。
  Ubuntu 毛坯房逼你自己刷墙、布线、装灯——这才是运维真本事。
  面试官问"你会Linux吗"，答"会用宝塔"=不及格。

- **为什么要 `sudo -i` 切root？**
  Linux里普通用户(admin)权限很小，装软件、改配置会被拦。
  `sudo` = 借管理员的权限，`-i` = 完全变成管理员(root)。
  比喻：普通员工拿钥匙开不了财务室，`sudo -i` 就是刷老板的卡。

### 踩的坑
```
Permission denied (publickey)
```
意思：服务器只认"密钥钥匙"，不认"密码钥匙"，本地直连进不去。
解法：用阿里云网页终端 Workbench / VNC（走内网VIP通道，相当于老板亲自带你进店）。

## 📍 第二阶段：装修前，先把工具货架上新

### 做了什么
```bash
apt update && apt upgrade -y
```

### 为什么
- `apt update` = **刷新菜单**：告诉系统"现在有哪些软件、最新版本是啥"。
  ⚠️ 它只更新清单，不动已装的软件。
- `apt upgrade` = **照新菜单换货**：把已装的旧软件升级到新版。
- 比喻：`update` 是问供应商"现在有啥新货"，`upgrade` 是"把旧货换成新货"。
- 为什么必须先做这步？因为不刷新菜单，下一步装Nginx可能装到过时版本或找不到包。

### 踩的坑
```
Waiting for cache lock: Could not get lock /var/lib/dpkg/...
```
原因：阿里云开机时，系统自己在后台悄悄更新(`unattended-upgrades`)，占用了"仓库钥匙"。
两个apt不能同时用一把钥匙。解法：等它跑完，或手动清掉锁。
比喻：供应商在盘点货架，你等着别抢。

## 📍 第三阶段：请一位接待员（装Nginx）

### 做了什么
```bash
apt install nginx -y      # 装Nginx
systemctl start nginx     # 启动接待员
systemctl enable nginx    # 设开机自启
systemctl status nginx    # 检查它活着没
```

### 为什么
- **Nginx是干嘛的？** 它是"接待员"。顾客(浏览器)来访问你的网站，Nginx负责把对应的网页文件递出去。
- 为什么用它不用Apache？Nginx更省内存、并发更高，是当下主流，简历也更好看。
- `systemctl` 是**系统服务管家**，统一负责各类后台服务的启动/停止/自启/查状态。
  - `start` = 让接待员上班
  - `enable` = 每天(每次开机)自动上班，不用你手动喊
  - `status` = 查他今天来没来

### 成功标志
`active (running)` = 接待员正常上班中。

## 📍 第四阶段：装门禁，只开该开的门（防火墙）

### 做了什么
```bash
ufw enable                # 启用门禁
ufw allow 'Nginx Full'    # 开80和443两扇门
ufw status                # 查看开了哪些门
```

### 为什么
- **防火墙ufw是干嘛的？** 店面的门禁系统。默认可以拦掉乱七八糟的连接，只让正常客人进。
- `Nginx Full` 是个"套餐名"，等于同时放行 **80(HTTP)** 和 **443(HTTPS)** 两个端口。
- 比喻：端口=店里的门。80是普通门，443是加密VIP门。门禁只给这两扇开门，其他全锁死，小偷(黑客扫描)进不来。

> ⚠️ 但注意：这只是"系统层面"的防火墙。阿里云还有一层"安全组"门禁，两边都得放行才能通。

## 📍 第五阶段：给店装隔音玻璃（HTTPS核心）

这是整个项目的**重头戏**，分3步。

### 5.1 请证书管理局工作人员（装Certbot）
```bash
apt install certbot python3-certbot-nginx -y
```
Certbot 是 Let's Encrypt 官方工具，能**免费申请+自动续签**证书。
现在先装上，等域名备案后就能申请正式证书。

### 5.2 先办一张临时营业执照（自签名证书）

#### 为什么现在用自签名不用正式证书？
申请正式 Let's Encrypt 证书，需要**一个已解析生效的域名**。
而国内服务器 + 域名，必须先**ICP备案**才能正常用域名访问。备案要7-20天。
所以：**先用自签名证书把HTTPS链路跑通**（证明你会配），等备案下来再换正式的。

```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/nginx-selfsigned.key \
  -out /etc/ssl/certs/nginx-selfsigned.crt
```

#### 逐词翻译：
| 词 | 大白话 |
|----|--------|
| `openssl req -x509` | 生成一张**自签名**证书（自己给自己开的执照） |
| `-nodes` | 私钥**不加密码**，不然Nginx每次启动要人工输密码 |
| `-days 365` | 有效期**1年** |
| `-newkey rsa:2048` | 顺便生成一对2048位的**加密钥匙** |
| `-keyout` | **私钥**存这（=店保险柜钥匙，绝不能外泄！） |
| `-out` | **证书**存这（=执照正本，可以给顾客看） |

#### 证书 vs 私钥，用比喻记牢：
- **证书(.crt)** = 餐厅挂在门口的"卫生等级A证书"，**人人可看**。
- **私钥(.key)** = 后厨保险柜的钥匙，**只有老板(服务器)有**。
- 顾客用证书里的"公开锁"加密信息，只有老板的私钥能解开 → 偷听无效。

验证权限（这是好习惯）：
```bash
ls -la /etc/ssl/private/nginx-selfsigned.key
```
看到 `.key` 是 `-rw-------`（只有root能看）= 正确！私钥必须保密。

### 5.3 告诉接待员"用加密模式营业"（配置Nginx）

写了两个 `server` 块（两块营业规则）：
- 一个监听 **80**（普通门）
- 一个监听 **443 ssl**（加密门），并 `include` 引入证书配置

```nginx
listen 443 ssl default_server;
include snippets/ssl-selfsigned.conf;   # 引用证书路径
```

### 5.4 改完配置的正确姿势（重要习惯！）
```bash
nginx -t                 # 先测试语法，没错才继续
systemctl reload nginx   # reload而非restart
```
- **`nginx -t` 为什么重要？** 配置写错直接重启，可能导致整个网站宕机。
  先 `-t` 体检一下，是运维的保命习惯。
- **`reload` vs `restart`？**
  `reload` = 悄悄换规则，正在接待的客人不受影响（不中断）。
  `restart` = 把店关门重装，所有在连的人都掉线。
  生产环境能用 `reload` 绝不用 `restart`。

## 📍 第六阶段：上架商品（部署仪表盘）

### 踩的大坑：403 Forbidden
访问HTTPS却显示403。为什么？
配置里写了 `index index.html;`（让接待员找index.html这个商品），
但目录里**根本没有index.html**，接待员找不到货 → 报403。
解法：把商品文件放进去即可。

### 踩的第二个坑：中文乱码
用 `echo '中文' > index.html` 传，页面中文全乱码。
**原因**：echo把中文当成"命令文字"，经过 Windows(GBK编码) → 传输通道 → Linux(UTF-8编码)，两套编码对不上，字就崩了。

**关键领悟**：
- 传**英文**：echo/printf 没问题
- 传**中文**：必须走**文件传输**或**服务器直接下载**（原样搬运字节，不翻译）

最终解法（优雅！）：让服务器自己去把已部署的仪表盘**下载**回来：
```bash
curl -L -o /var/www/html/index.html "https://你的外网地址/index.html"
```
- `-L` 跟随跳转，`-o` 存成指定文件。
- 这样200KB带中文的页面原封不动搬进来，**0乱码**。

### 面试官大概率追问 & 你的答案

| 追问 | 你的回答要点 |
|------|--------------|
| 证书和私钥区别？ | 证书公钥对外公示用于加密，私钥自己保密用于解密；私钥泄露=安全崩盘 |
| reload 和 restart 区别？ | reload 不中断现有连接热加载配置；restart 会断开所有连接，生产慎用 |
| HTTPS 怎么加密的？ | TLS握手：服务器出示证书→客户端验证→双方协商对称密钥→用对称密钥加密通信 |
| 自签名和CA证书区别？ | 自签名浏览器不信任会告警；CA(Let's Encrypt)签发受信任，需域名验证 |
| 为什么443而不是80？ | 80是HTTP明文，443是HTTPS标准端口，数据加密传输 |
| 你踩的坑印象最深？ | 中文乱码那个——让我理解了编码在传输链路里的重要性，不是所有问题都是程序错 |

## 📌 记住这几条"运维心法"

1. **先测后改**：`nginx -t` 是保命符，改配置永远先测语法
2. **能热不重启**：`reload` 优于 `restart`，生产环境零中断是专业素养
3. **私钥比命重要**：`.key` 权限永远 600，绝不外泄
4. **分层排查**：连不上先分清楚是"工具抽风"还是"服务挂了"（用端口测试定位）
5. **编码是个坑**：跨系统传中文，走文件/下载，别走命令字符
6. **知其所以然**：每条命令都问"为什么"，这才是运维和"会用宝塔"的区别
