# 检索增强生成（RAG）

## 是什么

RAG（Retrieval-Augmented Generation）让 LLM 在回答问题前先去外部知识库「翻资料」，把检索到的相关内容塞进上下文，再生成答案。相当于给 LLM 配了一个图书馆管理员。

## 为什么重要

LLM 有两大短板：知识截止训练日期、容易幻觉。RAG 同时解决了这两个问题——检索的是实时外部数据，生成的答案可以溯源到具体文档。

## 核心要点

- **三步流水线**：索引（文档切块→向量化→存库）→ 检索（问题向量化→相似度搜索）→ 生成（检索结果 + 问题 → LLM → 答案）。
- **文档切块**是 RAG 最被低估的环节：块太大检索不准，块太小丢失上下文，推荐 500-1000 token 带重叠。
- **Embedding 模型**决定了检索质量：中文推荐 `bge-large-zh`，多语言用 `text-embedding-3-large`。
- 向量数据库选型：小项目用 Chroma/FAISS 够用，生产级用 Milvus/Pinecone/Weaviate。
- **高级技巧**：HyDE（先生成假设答案再检索）、重排序（rerank）、多路召回（关键词+向量混合检索）。

## 一句话带走

> RAG = LLM + 搜索引擎。模型不知道的，先去查再回答。
