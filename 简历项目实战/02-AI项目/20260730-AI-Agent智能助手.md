# AI Agent 智能助手 — 让模型自己干活

## 📄 简历写法（可直接抄）

> **基于 Function Calling 的 AI Agent 自动化助手** · 项目角色：独立设计开发 · 2026.XX
>
> - 针对「数据查询→整理→报表→发送」类重复性工作（单次 **30 分钟**），开发具备**工具调用与多步规划**能力的 AI Agent
> - 封装 **8+ 个工具**（数据库查询、Excel 生成、邮件/钉钉发送、网页抓取等），Agent 自主拆解任务、按序调用、异常重试
> - 单任务处理时间降至 **2 分钟**，准确率 **95%+**，人工只做最终确认，每周节省 **10+ 小时**重复劳动

> [!tip] 旁批：Agent 和"调了一次 API"的区别（面试分水岭）
> 很多人把"LLM + 提示词"叫 Agent，面试官一问就露馅。真 Agent 三个特征：**① 自主决策下一步做什么（规划）② 能调工具获取外部信息/执行动作 ③ 有反馈循环（工具结果再喂回模型继续推理）**。你的项目讲清这三点，就站在"会调 API"的人前面了。

## 🛠️ 详细操作步骤

### 步骤 1：定义工具集（Agent 的"手和脚"）

```python
# tools.py —— 每个工具 = 一个函数 + 一段 JSON Schema 描述
import sqlite3
import pandas as pd

def query_sales_db(sql: str) -> str:
    """执行只读 SQL 查询，返回结果（最多 100 行）"""
    if not sql.strip().lower().startswith("select"):
        return "错误：仅允许 SELECT 查询"     # 安全护栏！
    conn = sqlite3.connect("sales.db")
    try:
        df = pd.read_sql_query(sql + " LIMIT 100", conn)
        return df.to_string(index=False)
    finally:
        conn.close()

def generate_excel(data: str, filename: str) -> str:
    """把 CSV 格式文本存成 Excel 文件"""
    from io import StringIO
    df = pd.read_csv(StringIO(data))
    df.to_excel(f"./output/{filename}", index=False)
    return f"文件已生成: ./output/{filename}"

def send_dingtalk(message: str) -> str:
    """发送钉钉消息到运营群"""
    import requests
    webhook = "https://oapi.dingtalk.com/robot/send?access_token=xxx"
    requests.post(webhook, json={"msgtype": "text", "text": {"content": message}})
    return "已发送"

# ---- 工具的 JSON Schema 描述（模型靠这个理解工具）----
TOOLS_SCHEMA = [
    {
        "type": "function",
        "function": {
            "name": "query_sales_db",
            "description": "查询销售数据库（SQLite）。表结构：sales(id, product, region, amount, date)",
            "parameters": {
                "type": "object",
                "properties": {
                    "sql": {"type": "string", "description": "SELECT 查询语句"}
                },
                "required": ["sql"]
            }
        }
    },
    # ... generate_excel / send_dingtalk 的 schema 同理
]

TOOL_MAP = {
    "query_sales_db": query_sales_db,
    "generate_excel": generate_excel,
    "send_dingtalk": send_dingtalk,
}
```

> [!important] 旁批：description 写得好，模型才会用
> Schema 里的 `description` 是模型决定"何时用、怎么用"这个工具的唯一依据。写"查询数据库"模型可能乱传 SQL；写清**表结构、字段含义、限制条件**，调用准确率立马上来。这和写提示词是同一门手艺。

### 步骤 2：实现 Agent 主循环（ReAct 模式，项目灵魂）

```python
# agent.py
import json
from openai import OpenAI

client = OpenAI(api_key="sk-xxx", base_url="https://api.deepseek.com")

SYSTEM_PROMPT = """你是一个运营数据助手。你可以使用工具完成任务。
工作规则：
1. 先分析任务需要哪几步，再逐步执行
2. 调用工具失败时，分析原因并重试（最多 3 次）
3. 数据相关的问题必须查数据库，禁止编造数字
4. 完成后向用户汇报：做了什么、结果摘要、产出文件位置"""

def run_agent(user_task: str, max_steps: int = 10):
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": user_task}
    ]

    for step in range(max_steps):
        resp = client.chat.completions.create(
            model="deepseek-chat",
            messages=messages,
            tools=TOOLS_SCHEMA,        # 把工具集告诉模型
            tool_choice="auto"
        )
        msg = resp.choices[0].message

        # ---- 情况 A：模型想调工具 ----
        if msg.tool_calls:
            messages.append(msg)     # 把模型的工具调用请求记入对话
            for call in msg.tool_calls:
                fn_name = call.function.name
                fn_args = json.loads(call.function.arguments)
                print(f"[步骤{step+1}] 调用工具: {fn_name}({fn_args})")

                try:
                    result = TOOL_MAP[fn_name](**fn_args)
                except Exception as e:
                    result = f"工具执行出错: {e}"   # 错误也喂回模型，让它自愈

                messages.append({
                    "role": "tool",
                    "tool_call_id": call.id,
                    "content": str(result)
                })

        # ---- 情况 B：模型给出最终答复，任务结束 ----
        else:
            print(f"[完成] 共执行 {step+1} 步")
            return msg.content

    return "达到最大步数限制，任务未完全完成"

# ---- 使用 ----
result = run_agent(
    "查一下上个季度各区域的销售额，生成 Excel 报表，"
    "然后把销量 TOP3 的区域和金额发到钉钉群"
)
print(result)
```

> [!important] 旁批：这个循环里藏着四个面试考点
> 1. **工具结果回喂**：`role: "tool"` 的消息把执行结果放回对话，模型据此决定下一步——这就是"反馈循环"
> 2. **错误自愈**：工具报错不中断，把错误信息给模型，它通常能修正参数重试——体现 Agent 的"鲁棒性"
> 3. **max_steps 保险丝**：防止模型陷入死循环烧钱，生产必须设
> 4. **全过程日志**：`[步骤N] 调用工具: xxx` 的轨迹既方便调试，也是给老板演示时的"哇塞时刻"

### 步骤 3：加一道安全护栏（体现工程思维）

```python
# 危险操作二次确认
DANGEROUS_TOOLS = {"send_dingtalk", "send_email"}

def confirm_before_run(fn_name, fn_args):
    if fn_name in DANGEROUS_TOOLS:
        print(f"⚠️ 即将执行: {fn_name}")
        print(f"   参数: {fn_args}")
        if input("   确认执行? (y/n): ").lower() != "y":
            return "用户取消了操作"
    return TOOL_MAP[fn_name](**fn_args)
```

> [!tip] 旁批：为什么"外发类"工具必须人工确认
> 查数据出错可以重来，发错群/发错邮件收不回来。业界共识：**Agent 自主性的边界画在"不可逆操作"之前**。面试讲这句，证明你考虑过 Agent 落地的真实风险，不是只会跑 demo。

## ❓ 面试高频问题

1. **Agent 和固定工作流的区别？** → 工作流每一步是写死的；Agent 由模型**根据中间结果动态决定**下一步。任务路径可预测用工作流（便宜稳定），路径不确定才用 Agent（灵活但贵、有幻觉风险）——这句"选型观"很加分
2. **怎么控制 Agent 不乱调工具？** → 工具白名单 + 危险操作人工确认 + max_steps 熔断 + 只读权限账号（数据库用 read-only 用户）
3. **ReAct 是什么？** → Reasoning + Acting：模型先输出"思考"再决定"动作"，交替进行。Function Calling 是它的工程实现
4. **多 Agent 了解吗？** → 复杂任务拆给不同专长的 Agent（研究员/写手/审校），由编排层协调。个人项目不必上，知道适用边界即可
5. **MCP 是什么？** → 模型上下文协议，把"工具接入"标准化——工具方按 MCP 标准实现一次，所有支持 MCP 的模型都能用。类似 AI 工具界的 USB-C
