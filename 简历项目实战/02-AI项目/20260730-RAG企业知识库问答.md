# RAG 企业知识库问答 — 当前最热的 AI 落地项目

## 📄 简历写法（可直接抄）

> **基于 RAG 的企业知识库智能问答系统** · 项目角色：全栈独立完成 · 2026.XX
>
> - 针对内部文档分散、新人查找知识平均耗时 **20 分钟/次** 的问题，基于 **LangChain + 向量数据库 + 国产大模型** 搭建检索增强问答系统
> - 完成「文档解析 → 智能切分 → 向量化 → 混合检索 → 重排序 → 答案生成」全链路，支持 **5000+ 页** PDF/Word/Markdown 文档
> - 问答首查命中率 **85%+**，知识获取时间从 20 分钟降至 **30 秒**，并支持答案溯源（点击跳转原文段落），有效抑制模型幻觉

> [!tip] 旁批：为什么 RAG 是简历第一 AI 项目
> 三个原因：① 它是企业 AI 落地的**第一大场景**（几乎每个公司都在做）；② 技术栈覆盖广——你能在 15 分钟面试里讲完从数据到前端的完整链路；③ 门槛低天花板高——跑通 demo 只要 200 行代码，但优化点（切分策略、混合检索、重排、幻觉抑制）每一个都能展开深聊，面试官往深挖你有东西接。

## 🧰 技术栈

| 工具 | 用途 | 为什么选它（面试考点） |
|------|------|------------------------|
| LangChain / LlamaIndex | RAG 编排框架 | 生态最全，组件化（加载器、切分器、检索器可插拔） |
| Chroma / Milvus | 向量数据库 | Chroma 零部署适合起步；Milvus 分布式支持亿级向量，简历上写 Milvus 更硬 |
| BGE-M3 / text-embedding-3 | 文本向量化 | BGE-M3 中文效果第一梯队且**开源免费**，支持稠密+稀疏混合 |
| DeepSeek / GLM-4 / Qwen | 答案生成 LLM | 国产 API 便宜（DeepSeek 百万 token 几块钱）、中文好、无需特殊网络 |
| BGE-Reranker | 检索结果重排序 | 检索粗排 + 重排精排是工业标配，召回质量提升明显 |
| FastAPI + Streamlit | 后端接口 + 前端界面 | Streamlit 50 行出可交互 demo，FastAPI 负责生产接口 |

### 步骤 1：文档加载与智能切分

```python
# ingest.py —— 文档入库管线
from langchain_community.document_loaders import PyPDFLoader, Docx2txtLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from pathlib import Path

def load_documents(doc_dir: str):
    docs = []
    for f in Path(doc_dir).rglob("*"):
        if f.suffix == ".pdf":
            docs.extend(PyPDFLoader(str(f)).load())
        elif f.suffix == ".docx":
            docs.extend(Docx2txtLoader(str(f)).load())
    return docs

# 切分：中文场景的关键参数
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,           # 每块 500 字
    chunk_overlap=80,         # 块间重叠 80 字，防止语义被切断
    separators=["\n\n", "\n", "。", "；", "，", " "],  # 中文分隔符优先
)

docs = load_documents("./company_docs")
chunks = splitter.split_documents(docs)
print(f"共切分 {len(chunks)} 个块")
```

> [!important] 旁批：切分是 RAG 效果的第一变量
> - **chunk_size 太大**：一块里混入多个主题，向量表达"什么都像什么都不像"，检索不准
> - **太小**：语义不完整，"报销流程的第三步是…"单独一块，检索到了也答不全
> - **overlap 的意义**：一句话被切在两半时，重叠区保证至少有一块含完整语义
> - 中文一定要把 `。；` 加进 separators，否则会按空格乱切（中文没空格）
> - 面试深挖就讲**语义切分**（按 embedding 相似度找切点）作为进一步优化方向

### 步骤 2：向量化与入库

```python
# 用开源 BGE-M3，本地跑不花钱
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_community.vectorstores import Chroma

embeddings = HuggingFaceEmbeddings(
    model_name="BAAI/bge-m3",
    model_kwargs={"device": "cpu"},      # 有 GPU 改 cuda，快 10 倍
    encode_kwargs={"normalize_embeddings": True}  # 归一化后用余弦相似度
)

vectordb = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db"
)
vectordb.persist()
```

### 步骤 3：检索 + 重排 + 生成（核心链路）

```python
# qa.py
from langchain_community.vectorstores import Chroma
from openai import OpenAI

# ---- 1. 向量检索（粗排）----
retriever = vectordb.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 10}          # 先捞 10 个候选
)

# ---- 2. 重排序（精排）----
from sentence_transformers import CrossEncoder
reranker = CrossEncoder("BAAI/bge-reranker-v2-m3")

def retrieve_and_rerank(query: str, top_k: int = 3):
    candidates = retriever.get_relevant_documents(query)
    pairs = [[query, doc.page_content] for doc in candidates]
    scores = reranker.predict(pairs)
    ranked = sorted(zip(candidates, scores), key=lambda x: x[1], reverse=True)
    return [doc for doc, _ in ranked[:top_k]]

# ---- 3. 组装 Prompt 生成答案 ----
client = OpenAI(
    api_key="sk-你的key",
    base_url="https://api.deepseek.com"   # DeepSeek API
)

def ask(question: str):
    docs = retrieve_and_rerank(question)
    context = "\n\n---\n\n".join(
        f"[文档{i+1}] {d.page_content}\n来源: {d.metadata.get('source')}"
        for i, d in enumerate(docs)
    )
    prompt = f"""你是企业知识库助手。仅根据以下参考资料回答问题：
1. 答案中标注引用来源，如[文档1]
2. 资料中没有的内容，明确说"知识库中未找到相关信息"，不要编造
3. 回答简洁，分点呈现

参考资料：
{context}

问题：{question}"""

    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.1          # 低温度，求稳不求创意
    )
    return resp.choices[0].message.content, docs

answer, sources = ask("报销流程需要哪些审批节点？")
print(answer)
```

> [!important] 旁批：抑制幻觉的三道防线（面试必考）
> 1. **Prompt 约束**：明确"只根据资料回答，没有就说没有"——成本最低，先做这个
> 2. **低 temperature**：0.1~0.3，减少自由发挥
> 3. **答案溯源**：每句话标注引用文档编号，用户可点击核验——这既是信任机制，也倒逼模型贴着资料说话
>
> 加上 reranker 后召回准确率通常提升 10~20%，这是"检索粗排+重排精排"两段式架构的价值。

### 步骤 4：Streamlit 前端（50 行出 demo）

```python
# app.py
import streamlit as st

st.set_page_config(page_title="企业知识库问答", page_icon="📚")
st.title("📚 企业知识库智能问答")

if "history" not in st.session_state:
    st.session_state.history = []

question = st.chat_input("请输入问题…")
if question:
    with st.spinner("检索中…"):
        answer, sources = ask(question)
    st.session_state.history.append((question, answer, sources))

for q, a, srcs in st.session_state.history:
    with st.chat_message("user"):
        st.write(q)
    with st.chat_message("assistant"):
        st.write(a)
        with st.expander("📎 查看引用来源"):
            for i, d in enumerate(srcs):
                st.caption(f"[文档{i+1}] {d.metadata.get('source')}")
                st.text(d.page_content[:200] + "…")
```

```bash
streamlit run app.py

```

### 步骤 5：FastAPI 生产接口（对接前端/钉钉/企微）

```python
# api.py
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Query(BaseModel):
    question: str

@app.post("/ask")
def ask_api(q: Query):
    answer, sources = ask(q.question)
    return {
        "answer": answer,
        "sources": [{"file": d.metadata.get("source")} for d in sources]
    }
```

## ❓ 面试高频问题

1. **RAG 和微调怎么选？** → 知识更新频繁/需要溯源 → RAG；需要改变模型行为风格/术语习惯 → 微调；实际项目两者常结合（先微调行业术语，再 RAG 挂实时知识）
2. **向量检索为什么不直接用关键词？** → 关键词匹配不懂语义（"辞退"和"解除劳动合同"是同一个意思但零重合词）；向量检索懂语义但漏精确匹配（工号、法条编号）→ 工业界做法是 **BM25 + 向量混合检索**
3. **怎么评估 RAG 系统效果？** → 构建测试问题集，看召回率（对的文档有没有被检索到）和答案忠实度（RAGAS 框架可自动化评估）
4. **文档更新了怎么办？** → 增量索引：按文件哈希判断是否变化，只重建变化文档的向量
5. **长文档怎么处理？** → 层级索引（先检索章节摘要，再下钻到块）或父子切分（小块检索、大块喂给模型保证上下文完整）
