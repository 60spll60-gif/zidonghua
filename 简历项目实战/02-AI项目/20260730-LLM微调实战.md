# LoRA 微调实战 — 消费级 GPU 定制行业模型

## 📄 简历写法（可直接抄）

> **垂直领域大模型 LoRA 微调** · 项目角色：独立完成 · 2026.XX
>
> - 针对通用大模型在**垂直领域（如：医疗问答/法务咨询/客服话术）** 专业术语理解弱、回复风格不符的问题，基于 **LLaMA-Factory + LoRA** 微调 Qwen2.5-7B
> - 构建 **3000+ 条**高质量指令数据集（含清洗、去重、格式统一），在单张 RTX 4090 上完成训练（成本 < ¥50）
> - 领域问答准确率从 **62% 提升至 89%**，术语使用规范度显著提升，并通过 **vLLM 部署上线**提供服务

> [!tip] 旁批：什么时候该微调、什么时候别微调（面试第一问）
> **该微调**：需要模型学会特定风格/术语/格式（客服话术、病历文书、代码规范），且这些知识稳定不变
> **不该微调**：知识频繁更新（今天的产品价目表明天就过时）→ 用 RAG；通用能力缺失（模型本身不会推理）→ 换更强的基座模型
> 一句话：**微调教"怎么说话"，RAG 教"说什么话"**。讲出这句，面试官就知道你不是跟风跑了个脚本。

## 🧰 技术栈

| 工具 | 用途 | 为什么选它 |
|------|------|------------|
| LLaMA-Factory | 微调框架 | 国产开源、Web UI 零代码、支持 LoRA/QLoRA 全参，社区活跃 |

## 🛠️ 详细操作步骤

### 步骤 1：构建数据集（最花时间的环节，占 60%）

```json
// data/domain_qa.json —— Alpaca 指令格式
[
  {
    "instruction": "患者问：感冒持续一周不退烧怎么办？",
    "input": "",
    "output": "持续一周不退烧提示可能并非普通感冒，建议：\n1. 尽快就医检查血常规+C反应蛋白，明确感染类型\n2. 排查流感、肺炎等并发症\n3. 就医前注意休息、多饮水\n⚠️ 本建议仅供参考，具体诊疗请遵医嘱。"
  },
  {
    "instruction": "把这段客服对话改写成标准安抚话术",
    "input": "客户：你们的产品太烂了，我要投诉！",
    "output": "非常抱歉给您带来了不好的体验，您反馈的问题我已详细记录。为尽快帮您解决，方便提供一下订单号吗？我会在 24 小时内给您答复。"
  }
]
```

> [!important] 旁批：数据质量 > 数据数量（核心认知）
> - **1000 条精品 > 10000 条垃圾**：错误、重复、风格不一的数据会"教坏"模型
> - **格式必须统一**：输出都要带"\n1. xxx\n2. xxx"就全带，别有的分点有的不分
> - **去重**：近重复样本（语义相似度 > 0.9）会让模型过拟合这几句
> - 数据来源：真实业务日志脱敏 > 强模型（GPT-4/DeepSeek）生成 > 手工编写。个人练习可用强模型生成 + 人工抽检
> - 面试追问"你的 3000 条怎么来的"——必须答得出构建流程，这是微调项目的真实性检验

### 步骤 2：租卡 + 装环境（10 分钟）

```bash
# AutoDL 租一张 RTX 4090（选 PyTorch 2.x 镜像）
# 安装 LLaMA-Factory
git clone https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory
pip install -e ".[torch,metrics]"

# 验证 GPU
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

### 步骤 3：配置训练（Web UI 或 YAML 二选一）

```bash
# 方式一：Web UI（推荐给初学者，可视化配置）
llamafactory-cli webui
# 浏览器打开 http://localhost:7860

# 方式二：YAML 命令行（可复现，适合简历展示）
```

```yaml
# train_lora.yaml
model_name_or_path: Qwen/Qwen2.5-7B-Instruct
stage: sft                        # 监督微调
do_train: true
finetuning_type: lora
lora_rank: 16                     # LoRA 秩：越大能力越强但越易过拟合
lora_alpha: 32                    # 一般设为 rank 的 2 倍
lora_target: all                  # 所有线性层都挂 LoRA
dataset: domain_qa                # 在 dataset_info.json 注册你的数据集
template: qwen                    # 对话模板必须和基座模型匹配！
cutoff_len: 2048
learning_rate: 1.0e-4             # LoRA 经典学习率
num_train_epochs: 3               # 3 轮足够，多了过拟合
per_device_train_batch_size: 4
gradient_accumulation_steps: 4    # 等效 batch_size = 4×4 = 16
bf16: true                        # 4090 支持 bf16，训练更稳
output_dir: saves/qwen-lora-v1
logging_steps: 10
save_steps: 500
```

```bash
llamafactory-cli train train_lora.yaml
# 7B + LoRA + 3000 条数据：约 1~2 小时，花费 ~¥3
```

> [!important] 旁批：三个最容易翻车的参数
> 1. **`template` 必须匹配基座模型**（Qwen 用 qwen，LLaMA 用 llama3）——配错了模型输出会胡言乱语，这是新手第一坑
> 2. **学习率**：LoRA 用 1e-4，全参微调用 1e-5~2e-5，差一个数量级；LoRA 用全参的学习率会不收敛
> 3. **epoch 不是越多越好**：3 轮左右最佳，10 轮以上基本都在背答案（过拟合），表现为"训练集完美、新问题翻车"

### 步骤 4：评估效果（没有评估的微调等于没做）

```bash
# 1. 训练曲线：loss 应平稳下降（LLaMA-Factory 自动生成 loss 图）
#    正常：0.9 → 0.3 缓降；异常：一开始就 0.01（数据泄露/过拟合）

# 2. 构建 50 道领域测试题（不能出现在训练集里！），微调前后各测一次
```

```python
# eval.py —— 简易对比评估
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")

test_cases = [
    {"q": "患者问：感冒药和降压药能一起吃吗？", 
     "keywords": ["遵医嘱", "间隔", "相互作用"]},  # 期望答案包含的要点
    # ... 50 道
]

def score(model_name):
    hit = 0
    for c in test_cases:
        resp = client.chat.completions.create(
            model=model_name,
            messages=[{"role": "user", "content": c["q"]}],
            temperature=0.1
        ).choices[0].message.content
        if all(k in resp for k in c["keywords"]):
            hit += 1
    return hit / len(test_cases)

# 微调前: 62%  →  微调后: 89%  ← 这个数字就是简历上的
```

> [!tip] 旁批：测试集绝对不能进训练集
> 这是机器学习的基本纪律，但微调时特别容易犯——数据是一起收集的，没分开。泄漏的后果：评估分数虚高（95%+），上线就露馅。简历上写"构建独立测试集评估"，懂行的面试官会点头。

### 步骤 5：合并权重 + 部署（闭环）

```bash
# LoRA 产出的是"适配器"（只有几百 MB），要合并进基座模型
llamafactory-cli export \
  --model_name_or_path Qwen/Qwen2.5-7B-Instruct \
  --adapter_name_or_path saves/qwen-lora-v1 \
  --export_dir models/qwen-domain-v1 \
  --export_size 2 \
  --export_legacy_format False

# 用你私有化部署项目里的 vLLM 直接加载
docker run -d --gpus all -p 8000:8000 \
  -v $(pwd)/models:/models \
  vllm/vllm-openai:latest \
  --model /models/qwen-domain-v1
```

至此完成闭环：**数据 → 训练 → 评估 → 部署 → 服务**。面试时可以画完整链路图。

## ❓ 面试高频问题

1. **LoRA 原理？** → 冻结原模型权重，在旁路训练一对低秩矩阵（A×B），用低秩分解近似权重更新量。16 秩的 LoRA 只需训练原模型 ~0.3% 的参数
2. **LoRA rank 怎么选？** → 8~64 常用。任务和基座差异小（风格调整）→ 8~16；差异大（新领域知识）→ 32~64。太大过拟合且失去省显存的意义
3. **QLoRA 是什么？** → 基座模型先量化到 4bit 再挂 LoRA，显存需求再降一半，单卡 24G 可微调 32B——代价是轻微精度损失
4. **SFT 之后还有 DPO/RLHF，了解吗？** → SFT 教模型"怎么答"，DPO/RLHF 教模型"哪个答案更好"（偏好对齐）。垂直场景 SFT 通常够用，回答质量有明确优劣对时再上 DPO
5. **微调后模型忘了通用能力怎么办？** → 灾难性遗忘。对策：混入 10~20% 通用指令数据一起训练；降低学习率和 epoch；或干脆只 LoRA（基座权重没动，随时摘掉适配器还原）
