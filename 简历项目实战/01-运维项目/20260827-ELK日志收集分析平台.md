# ELK Stack 日志收集与分析平台

## 📄 简历写法（可直接抄）

> **ELK日志收集与分析平台** · 项目角色：主导搭建 · 2026.XX
>
> - 针对分布式系统**日志分散难以集中查看**、故障排查**需要登录多台服务器逐个检查**的问题，基于 **Elasticsearch + Logstash + Kibana + Filebeat** 设计并实现企业级日志收集与分析平台
> - 实现**全链路日志集中管理**，故障定位时间从 **2小时** 缩短至 **5分钟**，日志查询效率提升 **90%**

| 工具 | 用途 | 为什么选它（面试考点） |
|------|------|------------------------|
| Elasticsearch 8.x | 日志存储与搜索引擎 | 分布式、近实时、全文搜索、RESTful API |
| Logstash 8.x | 日志收集、解析、转换 | 强大的数据处理管道，支持多种输入输出 |

## 🛠️ 详细操作步骤

### 步骤 0：准备环境

**在哪里操作**：您的本地电脑（Windows/Mac/Linux都可以）

**操作目的**：准备一台云服务器作为实验环境

```bash
# 1. 购买云服务器（推荐配置）
# - 阿里云/腾讯云/华为云 学生机（约¥10/月）
# - 配置：4核CPU、8GB内存、80GB硬盘（ELK比较吃内存）
# - 系统：Ubuntu 22.04 LTS（推荐）
# - 注意：ELK至少需要8GB内存，4GB会很卡

# 2. 登录服务器（在本地电脑终端执行）
# Windows用户：使用PowerShell或Git Bash
# Mac/Linux用户：打开终端
ssh root@你的服务器IP

# 3. 更新系统（必须执行）
sudo apt update && sudo apt upgrade -y

# 4. 安装必要工具
sudo apt install -y curl wget git vim net-tools
```

> [!warning] 旁批：内存要求
> Elasticsearch默认JVM堆内存是1GB，但建议设置为物理内存的一半。8GB内存的服务器，建议设置为4GB。

### 步骤 1：安装Docker和Docker Compose

**在哪里操作**：SSH连接到您的云服务器

**操作目的**：安装容器化环境

```bash
# 1. 安装Docker
curl -fsSL https://get.docker.com | sh

# 2. 启动Docker并设置开机自启
sudo systemctl start docker
sudo systemctl enable docker

# 3. 将当前用户添加到docker组（免sudo执行docker命令）
sudo usermod -aG docker $USER

# 4. 重新登录服务器（使组权限生效）
exit
ssh root@你的服务器IP

# 5. 验证Docker安装
docker --version
# 应该显示类似：Docker version 24.0.7

# 6. 安装Docker Compose
sudo apt install -y docker-compose-plugin

# 7. 验证Docker Compose安装
docker compose version
# 应该显示类似：Docker Compose version v2.23.3
```

**代码解释**：
- `curl -fsSL https://get.docker.com | sh`：一键安装Docker官方脚本
- `usermod -aG docker $USER`：将当前用户添加到docker组，这样就不需要每次sudo
- `docker compose`：Docker官方的多容器编排工具（旧版本是`docker-compose`）

> [!tip] 旁批：为什么用Docker部署ELK
> 手动安装ELK需要配置Java、Elasticsearch、Logstash、Kibana等多个组件，非常复杂。Docker一键部署，几分钟就能跑起来。

### 步骤 3：配置Elasticsearch

**在哪里操作**：SSH连接到您的云服务器

**操作目的**：配置Elasticsearch搜索引擎

```bash
# 1. 创建Elasticsearch配置文件
cat > /opt/elk/config/elasticsearch/elasticsearch.yml << 'EOF'
# 集群名称
cluster.name: "elk-cluster"

# 节点名称
node.name: "elasticsearch-1"

# 数据存储路径
path.data: /usr/share/elasticsearch/data

# 日志存储路径
path.logs: /usr/share/elasticsearch/logs

# 网络设置
network.host: 0.0.0.0
http.port: 9200

# 集群发现设置（单节点模式）
discovery.type: single-node

# 内存锁定（重要！防止使用swap）
bootstrap.memory_lock: true

# 安全设置（生产环境必须配置）
xpack.security.enabled: false
xpack.security.enrollment.enabled: false

# 性能优化
indices.memory.index_buffer_size: 20%
thread_pool.write.queue_size: 1000
EOF

# 2. 创建Elasticsearch环境变量文件
cat > /opt/elk/config/elasticsearch/.env << 'EOF'
# JVM堆内存设置（建议物理内存的一半）
ES_JAVA_OPTS="-Xms2g -Xmx2g"

# 环境变量
ELASTIC_PASSWORD=changeme
DISCOVERY_TYPE=single-node
xpack.security.enabled=false
EOF

# 3. 设置数据目录权限
sudo chown -R 1000:1000 /opt/elk/data/elasticsearch
```

**代码解释**：
- `cluster.name`：Elasticsearch集群名称，同一集群的所有节点必须相同
- `node.name`：当前节点名称，必须唯一
- `network.host: 0.0.0.0`：监听所有网络接口，允许外部访问
- `discovery.type: single-node`：单节点模式，不需要配置集群发现
- `bootstrap.memory_lock: true`：锁定内存，防止使用swap，提升性能
- `ES_JAVA_OPTS`：JVM堆内存设置，`-Xms`是初始大小，`-Xmx`是最大大小

> [!warning] 旁批：内存锁定
> 如果出现"memory locking failed"错误，需要禁用swap：
> ```bash
> sudo swapoff -a
> sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab
> ```

### 步骤 4：配置Logstash

**在哪里操作**：SSH连接到您的云服务器

**操作目的**：配置日志收集和处理管道

```bash
# 1. 创建Logstash配置文件
cat > /opt/elk/config/logstash/logstash.yml << 'EOF'
# HTTP API设置
http.host: "0.0.0.0"
http.port: 9600

# 持久化队列（防止数据丢失）
queue.type: persisted
queue.max_bytes: 1gb

# 日志级别
log.level: info

# 监控设置
xpack.monitoring.enabled: false
EOF

# 2. 创建Logstash管道配置（核心！）
cat > /opt/elk/config/logstash/pipeline/logstash.conf << 'EOF'
# 输入配置：从Filebeat接收日志
input {
  beats {
    port => 5044
  }
  
  # 可选：直接读取文件（用于测试）
  # file {
  #   path => "/var/log/*.log"
  #   start_position => "beginning"
  # }
}

# 过滤配置：解析和转换日志
filter {
  # 解析JSON格式日志
  if [message] =~ /^\{/ {
    json {
      source => "message"
      target => "parsed"
      skip_on_invalid_json => true
    }
  }
  
  # 解析Nginx日志格式
  if [fileset][name] == "access" {
    grok {
      match => { 
        "message" => "%{COMBINEDAPACHELOG}" 
      }
    }
    date {
      match => [ "timestamp", "dd/MMM/yyyy:HH:mm:ss Z" ]
    }
    geoip {
      source => "clientip"
    }
  }
  
  # 解析系统日志（syslog）
  if [fileset][module] == "system" {
    grok {
      match => { 
        "message" => "%{SYSLOGTIMESTAMP:syslog_timestamp} %{SYSLOGHOST:syslog_hostname} %{DATA:syslog_program}(?:\[%{POSINT:syslog_pid}\])?: %{GREEDYDATA:syslog_message}" 
      }
    }
  }
  
  # 添加字段
  mutate {
    add_field => { 
      "environment" => "production"
      "project" => "elk-demo"
    }
    remove_field => [ "host" ]
  }
  
  # 过滤健康检查日志（减少噪音）
  if [message] =~ /healthcheck|heartbeat/ {
    drop { }
  }
}

# 输出配置：发送到Elasticsearch
output {
  elasticsearch {
    hosts => ["http://elasticsearch:9200"]
    index => "%{[@metadata][beat]}-%{[@metadata][version]}-%{+YYYY.MM.dd}"
    user => "elastic"
    password => "${ELASTIC_PASSWORD}"
  }
  
  # 可选：同时输出到控制台（调试用）
  # stdout {
  #   codec => rubydebug
  # }
}
EOF

# 3. 设置Logstash配置目录权限
sudo chmod -R 755 /opt/elk/config/logstash
```

**代码解释**：
- **input**：定义日志输入源，这里使用Filebeat的beats输入
- **filter**：定义日志处理管道，包括：
  - `json`：解析JSON格式日志
  - `grok`：使用正则表达式解析文本日志
  - `date`：解析时间戳
  - `geoip`：根据IP地址获取地理位置
  - `mutate`：修改字段（添加、删除、重命名）
  - `drop`：丢弃不需要的日志
- **output**：定义日志输出目标，发送到Elasticsearch
- `%{[@metadata][beat]}`：使用Filebeat的元数据作为索引名

> [!tip] 旁批：Grok模式
> Grok是Logstash最强大的过滤器，可以解析复杂的文本格式。常用模式：
> - `%{IP:clientip}`：匹配IP地址
> - `%{TIMESTAMP_ISO8601:timestamp}`：匹配ISO8601时间格式
> - `%{GREEDYDATA:message}`：匹配任意内容

### 步骤 6：创建Docker Compose文件

**在哪里操作**：SSH连接到您的云服务器

**操作目的**：定义ELK服务编排

```bash
# 1. 创建docker-compose.yml
cat > /opt/elk/docker-compose.yml << 'EOF'
version: '3.8'

services:
  # Elasticsearch服务
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.12.0
    container_name: elasticsearch
    environment:
      - discovery.type=single-node
      - ES_JAVA_OPTS=-Xms2g -Xmx2g
      - xpack.security.enabled=false
      - bootstrap.memory_lock=true
    ulimits:
      memlock:
        soft: -1
        hard: -1
    volumes:
      - ./data/elasticsearch:/usr/share/elasticsearch/data
      - ./config/elasticsearch/elasticsearch.yml:/usr/share/elasticsearch/config/elasticsearch.yml
    ports:
      - "9200:9200"
      - "9300:9300"
    networks:
      - elk
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "curl -s http://localhost:9200/_cluster/health | grep -q '\"status\":\"green\"\\|\"status\":\"yellow\"'"]
      interval: 30s
      timeout: 10s
      retries: 5

  # Logstash服务
  logstash:
    image: docker.elastic.co/logstash/logstash:8.12.0
    container_name: logstash
    environment:
      - LS_JAVA_OPTS=-Xms1g -Xmx1g
    volumes:
      - ./config/logstash/logstash.yml:/usr/share/logstash/config/logstash.yml
      - ./config/logstash/pipeline:/usr/share/logstash/pipeline
      - ./data/logstash:/usr/share/logstash/data
    ports:
      - "5044:5044"
      - "9600:9600"
    networks:
      - elk
    depends_on:
      elasticsearch:
        condition: service_healthy
    restart: unless-stopped

  # Kibana服务
  kibana:
    image: docker.elastic.co/kibana/kibana:8.12.0
    container_name: kibana
    environment:
      - ELASTICSEARCH_HOSTS=http://elasticsearch:9200
      - ELASTICSEARCH_USERNAME=elastic
      - ELASTICSEARCH_PASSWORD=changeme
    volumes:
      - ./config/kibana/kibana.yml:/usr/share/kibana/config/kibana.yml
    ports:
      - "5601:5601"
    networks:
      - elk
    depends_on:
      elasticsearch:
        condition: service_healthy
    restart: unless-stopped

  # Filebeat服务（日志收集器）
  filebeat:
    image: docker.elastic.co/beats/filebeat:8.12.0
    container_name: filebeat
    user: root
    volumes:
      - ./config/filebeat/filebeat.yml:/usr/share/filebeat/filebeat.yml:ro
      - /var/log:/var/log:ro
      - /var/lib/docker/containers:/var/lib/docker/containers:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
    networks:
      - elk
    depends_on:
      elasticsearch:
        condition: service_healthy
    restart: unless-stopped

networks:
  elk:
    driver: bridge
EOF

# 2. 创建Filebeat配置目录和文件
mkdir -p /opt/elk/config/filebeat

cat > /opt/elk/config/filebeat/filebeat.yml << 'EOF'
filebeat.inputs:
  # 收集系统日志
  - type: log
    enabled: true
    paths:
      - /var/log/*.log
      - /var/log/syslog
      - /var/log/auth.log
    fields:
      log_type: system
    fields_under_root: true

  # 收集Docker容器日志
  - type: container
    enabled: true
    paths:
      - /var/lib/docker/containers/*/*.log
    processors:
      - add_docker_metadata: ~

  # 收集Nginx日志（如果安装了Nginx）
  - type: log
    enabled: true
    paths:
      - /var/log/nginx/access.log
      - /var/log/nginx/error.log
    fields:
      log_type: nginx
    fields_under_root: true

# 输出到Logstash
output.logstash:
  hosts: ["logstash:5044"]
  loadbalance: true

# 输出到Elasticsearch（可选，跳过Logstash直接输出）
# output.elasticsearch:
#   hosts: ["elasticsearch:9200"]
#   protocol: "http"

# 监控设置
monitoring.enabled: false
EOF
```

**代码解释**：
- **elasticsearch**：配置单节点模式、JVM内存、数据卷挂载
- **logstash**：依赖Elasticsearch，配置管道文件挂载
- **kibana**：依赖Elasticsearch，配置界面语言
- **filebeat**：收集宿主机日志，挂载`/var/log`和Docker日志目录
- **healthcheck**：健康检查，确保Elasticsearch完全启动后其他服务才启动
- **depends_on**：定义服务启动顺序

> [!warning] 旁批：版本兼容性
> ELK三个组件版本必须一致！8.12.0是目前稳定的版本，不建议混用不同版本。

### 步骤 7：启动ELK服务

**在哪里操作**：SSH连接到您的云服务器

**操作目的**：启动ELK容器集群

```bash
# 1. 进入项目目录
cd /opt/elk

# 2. 拉取Docker镜像（第一次需要，约2GB）
docker compose pull

# 3. 启动所有服务（后台运行）
docker compose up -d

# 4. 查看服务状态
docker compose ps
# 应该看到4个服务都是running状态

# 5. 查看日志（启动过程）
docker compose logs -f
# 按Ctrl+C退出日志查看

# 6. 等待服务完全启动（约1-2分钟）
# 检查Elasticsearch是否就绪
curl -s http://localhost:9200/_cluster/health?pretty
# 应该看到："status" : "green" 或 "yellow"

# 7. 检查Kibana是否就绪
curl -s http://localhost:5601/api/status | python3 -m json.tool
# 应该看到："status" : {"overall" : {"level" : "available"}}
```

**代码解释**：
- `docker compose up -d`：后台启动所有容器
- `docker compose ps`：查看容器状态
- `docker compose logs -f`：实时查看日志（`-f`表示跟随）
- `_cluster/health`：Elasticsearch集群健康API

> [!tip] 旁批：首次启动较慢
> 第一次启动需要初始化Elasticsearch索引，可能需要1-2分钟。如果看到"yellow"状态是正常的（单节点模式下没有副本分片）。

### 步骤 9：创建Index Pattern

**在哪里操作**：Kibana界面

**操作目的**：让Kibana识别Elasticsearch索引

```bash
# 1. 在Kibana界面，进入 Management → Stack Management → Index Patterns

# 2. 点击 "Create index pattern"

# 3. 输入索引模式名称
# Filebeat索引格式：filebeat-8.12.0-*
# 输入：filebeat-*
# 点击 "Next step"

# 4. 选择时间字段
# 选择：@timestamp
# 点睛 "Create index pattern"

# 5. 进入 Discover页面
# 在左上角选择刚创建的索引模式
# 应该能看到日志数据了
```

**代码解释**：
- Index Pattern告诉Kibana如何匹配Elasticsearch索引
- `filebeat-*`匹配所有以filebeat-开头的索引
- `@timestamp`是日志的时间戳字段，用于时间筛选

### 步骤 10：配置日志收集（测试用例）

**在哪里操作**：SSH连接到您的云服务器

**操作目的**：生成测试日志验证平台工作

```bash
# 1. 创建测试日志生成脚本
cat > /opt/elk/test-logs.sh << 'EOF'
#!/bin/bash

# 生成系统日志
echo "$(date) [INFO] 系统启动完成" | sudo tee -a /var/log/test-app.log
echo "$(date) [WARN] 磁盘空间不足80%" | sudo tee -a /var/log/test-app.log
```

### 步骤 13：配置日志保留策略

**在哪里操作**：SSH连接到您的云服务器

**操作目的**：防止磁盘空间耗尽

```bash
# 1. 创建生命周期管理策略
cat > /opt/elk/config/elasticsearch/lifecycle-policy.json << 'EOF'
{
  "policy": {
    "phases": {
      "hot": {
        "min_age": "0ms",
        "actions": {
          "rollover": {
            "max_primary_shard_size": "10gb",
            "max_age": "1d"
          }
        }
      },
      "warm": {
        "min_age": "7d",
        "actions": {
          "shrink": {
            "number_of_shards": 1
          },
          "forcemerge": {
            "max_num_segments": 1
          }
        }
      },
      "cold": {
        "min_age": "30d",
        "actions": {
          "freeze": {}
        }
      },
      "delete": {
        "min_age": "90d",
        "actions": {
          "delete": {}
        }
      }
    }
  }
}
EOF

# 2. 应用生命周期策略
curl -X PUT "http://localhost:9200/_ilm/policy/log-lifecycle-policy" \
  -H 'Content-Type: application/json' \
  -d @/opt/elk/config/elasticsearch/lifecycle-policy.json

# 3. 应用到Filebeat索引模板
curl -X PUT "http://localhost:9200/_index_template/filebeat" \
  -H 'Content-Type: application/json' \
  -d '{
    "index_patterns": ["filebeat-*"],
    "template": {
      "settings": {
        "index.lifecycle.name": "log-lifecycle-policy",
        "index.lifecycle.rollover_alias": "filebeat"
      }
    }
  }'
```

**代码解释**：
- **hot阶段**：最新日志，每天或每10GB滚动一次
- **warm阶段**：7天后的日志，合并分片，提升查询性能
- **cold阶段**：30天后的日志，冻结索引，节省内存
- **delete阶段**：90天后自动删除

> [!warning] 旁批：生产环境建议
> 生产环境日志保留时间根据合规要求设置，金融行业通常要求保留180天或更长。

## ❓ 面试高频问题

### 1. **ELK三个组件分别负责什么？**
- **Elasticsearch**：分布式搜索引擎，负责存储和检索日志数据
- **Logstash**：数据处理管道，负责收集、解析、转换日志
- **Kibana**：可视化界面，负责展示和分析日志数据
- **补充组件**：Filebeat（轻量级日志收集器）、Beats（各种数据收集器）

### 2. **为什么用Filebeat而不是Logstash收集日志？**
- **资源占用**：Filebeat用Go语言编写，占用资源极少（约10MB内存）
- **可靠性**：Filebeat有背压机制，不会压垮下游服务
- **稳定性**：Filebeat专门为日志收集设计，稳定性更好
- **架构**：Filebeat → Logstash → Elasticsearch（分工明确）

### 3. **Elasticsearch的索引是什么？和数据库的表有什么区别？**
- **索引**：类似于数据库的表，但更灵活
- **文档**：类似于表中的行，JSON格式
- **字段**：类似于表中的列
- **区别**：
  - 数据库需要预定义Schema，Elasticsearch可以动态添加字段
  - 数据库适合事务处理，Elasticsearch适合搜索和分析
  - 数据库有ACID，Elasticsearch是近实时（1秒延迟）

### 4. **如何保证日志不丢失？**
- **Filebeat**：本地持久化队列，断线重连后继续发送
- **Logstash**：持久化队列，数据先写磁盘再处理
- **Elasticsearch**：副本分片，默认1个副本，数据冗余存储
- **网络层面**：使用TCP协议，确保数据完整传输

### 5. **日志量很大时如何优化？**
- **索引策略**：按时间滚动索引（每天一个索引）
- **生命周期管理**：自动清理过期数据
- **分片优化**：合理设置分片数量（单个分片建议10-50GB）
- **硬件优化**：SSD硬盘、充足内存、多核CPU
- **查询优化**：避免全量查询，使用时间范围过滤

### 6. **如何监控ELK本身的健康状态？**
```bash
# 1. Elasticsearch健康检查
curl -s http://localhost:9200/_cluster/health?pretty
# 关注：status、number_of_nodes、active_shards

# 2. 索引状态
curl -s http://localhost:9200/_cat/indices?v
# 关注：health、status、docs.count、store.size

# 3. 节点状态
curl -s http://localhost:9200/_cat/nodes?v
# 关注：heap.percent、disk.avail、load

# 4. 使用Kibana Stack Monitoring
# 在Kibana界面进入 Stack Monitoring
# 可以图形化监控所有组件
```

### 7. **生产环境ELK集群如何部署？**
- **Elasticsearch**：至少3个节点，1主2从，分布在不同可用区
- **Logstash**：至少2个节点，负载均衡
- **Kibana**：1个节点，挂了不影响数据
- **Filebeat**：每台服务器部署一个
- **负载均衡**：前面加Nginx或HAProxy
- **安全**：开启SSL/TLS、配置认证和授权
